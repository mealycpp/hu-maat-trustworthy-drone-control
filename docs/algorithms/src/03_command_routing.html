1. Purpose and context

The frozen HU model knows nine primitive actions; it has no formation, yaw-turn-with-angle, spin or multi-aircraft travel vocabulary, and feeding such sentences to a closed-label classifier can map them onto a wrong primitive (for example a formation request classified as STOP). The router decides, deterministically and before any inference, whether an utterance (a) is refused, (b) becomes an operator-confirmed deterministic mission proposal, (c) is handed to the trained HU model, or (d) is shown to HU with execution forbidden. Every mission proposal is labelled as not originating from the trained model and requires explicit operator confirmation.

2. Inputs, outputs

Input: normalised utterance (after Algorithm 2 declined it). Output of parse(text): one of None (route to HU), {error} (refuse), {error, unrecognized: true} (HU shown, never executed), or {action, targets, params, label, reason} with action ∈ {formation, spin, turn, takeoff, land, hover, move}. In the bridge, a proposal becomes a CONFIRM-band pending entry of kind mission (90 s, single use) and is sent on confirmation to /api/mission/dispatch with operator_confirmed=true and planner tag HU-MISSION-V6.

6. Complexity

A fixed cascade of regular-expression searches; the shape scan is O(|SHAPES|·|s|). Overall O(|s|) with a constant of a few dozen patterns. Measured routing latency is recorded per decision (latency_ms); no aggregate here.

7. Properties

Guaranteed

  • Fail-closed: every branch either refuses with a reason, proposes a single action requiring operator confirmation, or delegates to HU; there is no default action.
  • Compound refusal: sequential markers and verb combinations are refused instead of silently executing one part ("take off and move forward 1 meter").
  • Formation, turn, spin and multi-aircraft move vocabulary never reaches the closed-label model.
  • A list of names joined by and or commas is an address, not a compound ("Ra and Thoth, take off" reaches HU as a plain primitive); two actions joined by and ("land and turn left") are refused.
  • Sentences with no recognised flight structure are shown to the model for transparency but cannot execute (enforced in Algorithm 1).
  • Attribution: proposals carry the label "Deterministic simulator mission route ... not trained HU"; decision records carry decision_source.

Not guaranteed / limitations

  • Coverage is lexical. Words such as up, back, right trigger the MOVE branch even in non-motion prose; such cases then fail on direction/distance requirements (refusal, not execution).
  • A plain primitive with an unaddressed verb ("land") returns the address error from Algorithm 4 rather than reaching HU, because problem is checked before PLAIN-PRIMITIVE.
  • Spoken number words are limited to the WORDS table (e.g. no "twenty five"); the turn angle requires digits.
  • Routing does not check feasibility; feasibility is decided by the supervisor (Algorithms 5–10) after confirmation.

9. Comparison with alternatives and related work

Mapping an utterance to an executable action is semantic parsing. The router is a hand-written, regular-expression cascade; the alternatives below are learned or grammar-based parsers and language-model tool calling.

  • Learned grammar-based semantic parsing [1]: a probabilistic combinatory categorial grammar is induced from sentences paired with logical forms; outputs are compositional (sequences, conjunctions, nested arguments).
  • Grounded command understanding for robots [2]: Generalized Grounding Graphs build a probabilistic model from the command's structure and ground phrases to objects, places and paths in the environment.
  • Constrained decoding with a language model [3]: the model paraphrases input into a controlled canonical sublanguage under a grammar constraint, which maps deterministically to a meaning representation; only grammatical outputs can be produced.
  • Language-model tool / function calling [4, 5]: a model selects and fills API calls; [5] applies prompting with a high-level function library to robots including aerial navigation in simulation.

Where the router is weaker. Its coverage is lexical and small: paraphrases, synonyms outside the tables, spelled numbers beyond the WORDS table and any sequencing are refused, and no learning or measurement of coverage on real operator speech exists. It cannot express multi-step missions, which [1], [3] and [4, 5] can. Where it differs. It never invents an aircraft, an action or a parameter, its latency is a regular-expression scan, it runs without network or model, and its output is always either a refusal or a single proposal that the operator must confirm. A learned parser placed behind the same confirmation step and supervisor checks would be a compatible extension.
