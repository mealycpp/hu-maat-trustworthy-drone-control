1. Purpose and context

A formation command gives 2–5 airborne aircraft new horizontal slots at a common altitude. The planner must choose which aircraft takes which slot so that the simultaneous transition does not bring two aircraft too close, and must keep clear of aircraft that are not part of the formation (for example a faulted aircraft hovering mid-arena). It is a small, bounded, non-learning planner: exhaustive search over assignments with a sampled geometric check. It produces setpoints, not trajectories; the low-level controller and the proximity watchdog (Algorithm 7) remain responsible at run time.

3. Algorithm

Algorithm 5.1 SLOTS (geometry)
Source: festival/formation_planner.py: slots
1function SLOTS(shape, n)
2 require 2 ≤ n ≤ 5
3 S ← shape template (closed-form or fixed table truncated to n points) // e.g. line: (1.15(i−(n−1)/2), 0)
4 if shape is DERIVED (base, [a b; c d]) then S ← [ (a·x + b·y, c·x + d·y) for (x,y) in SLOTS(base, 5) ][:n]
5 c ← centroid(S); S ← S − c // centre on the arena origin
6 if any |x| > 3.0 or |y| > 3.0 then raise "exceeds arena"
7 if any pair of slots closer than 0.88 m then raise "separation too small"
8 return S
Algorithm 5.2 ASSIGN (permutation search with sampled conflict check)
Source: festival/formation_planner.py: assign
9function ASSIGN(P, drones, S, O)
10 cur ← [ (x,y,z) of p ∈ P ]; obs ← [ (x,y,z) of o ∈ O ]; best ← None
11 for each permutation π of S do // n! ≤ 120 candidates
12 g_i ← (π_i.x, π_i.y, 1.90)
13 if ∃ i, o: ‖g_i.xy − o.xy‖ < 0.88 then continue // slot must also be a safe parking spot (vertical landing)
14 for k = 0..40 do // f = k/40, all movers advance together
15 q_i ← cur_i + (g_i − cur_i)·k/40
16 if ∃ i<j: ‖q_i − q_j‖ < 0.88 then reject π
17 if ∃ i, o: ‖q_i − o‖ < 0.88 then reject π
18 cost ← Σ_i ‖g_i − cur_i‖²
19 if best = None or cost < best.cost then best ← (cost, π) // strict <: first optimum kept
20 if best = None then raise "No separation-safe straight-line assignment"
21 return best.π
Algorithm 5.3 ASSIGN-SHIFTED (translated placement around non-participants)
Source: festival/formation_planner.py: assign_shifted; festival/control_server_hu.py: Fleet.formation
22function ASSIGN-SHIFTED(P, drones, S, O, step = 0.35, max_shift = 1.75)
23 D ← [(0,0)] ++ [ (r cos(aπ/8), r sin(aπ/8)) : r = k·step, k = 1..5, a = 0..15 ] // 81 offsets, nearest ring first
24 for (dx,dy) in D do
25 S' ← S + (dx,dy)
26 if any slot of S' has |x| > 3.0 or |y| > 3.0 then continue
27 try return (ASSIGN(P, drones, S', O), (dx,dy))
28 except no-assignment: remember error
29 raise last error
30procedure FORMATION(shape, targets) // supervisor, under the fleet lock
31 P ← fleet-ordered targets; require |P| ≥ 2
32 require all five aircraft have fresh odometry; require no participant faulted
33 require every participant in {HOVER, MOVE, FORMATION, TURN, SPIN} and z ≥ 0.70
34 S ← SLOTS(shape, |P|); O ← fleet \ P
35 if O ≠ ∅ then (slots, off) ← ASSIGN-SHIFTED(P, dr, S, O) else slots ← ASSIGN(P, dr, S, ∅)
36 for each participant: target ← (slot.x, slot.y, 1.90); mode ← FORMATION

6. Complexity

ASSIGN: n! permutations × 41 samples × (C(n,2) + n·|O|) distance evaluations; for n = 5, |O| = 0: 120 × 41 × 10 ≈ 4.9·104. ASSIGN-SHIFTED multiplies this by at most 81 (n = 4, |O| = 1: 24 × 41 × 10 × 81 ≈ 8·105). Factorial in n; acceptable only because n ≤ 5. The plan is computed while the supervisor holds the fleet lock (the 10 Hz control loop waits for it); the dry-run path of Algorithm 10 runs it outside the lock.

7. Properties

Guaranteed (on the model used)

  • Every returned slot lies inside ±3.0 m and every pair of slots is ≥ 0.88 m apart.
  • If movers travel on straight lines at speeds proportional to their leg lengths (all arriving together), no sampled instant has two movers, or a mover and a stationary aircraft, closer than 0.88 m in 3D.
  • No slot is horizontally within 0.88 m of a non-participant, so participants can later land vertically next to it.
  • The returned assignment minimises the sum of squared leg lengths among the feasible permutations (exact, exhaustive). Deterministic for a given input.
  • Formation geometry is never squeezed to avoid obstacles: only translation is tried; failure is a refusal.

Not guaranteed

  • The motion model is not the controller. The supervisor (Algorithm 9) clamps each horizontal velocity axis to 0.62 m/s and the vertical to 0.45 m/s with a PD law, so real paths are neither straight nor synchronised; the sampled check is a heuristic, not a proof.
  • Sampling at 1/40 of the path can miss a closer approach between samples (for legs up to ~5 m, a sample spacing of ~0.13 m).
  • Non-participants are assumed stationary for the duration.
  • Minimum-cost is in squared distance, not time; longest-leg (makespan) is not minimised.
  • Assignment is not stable across small position changes (ties and near-ties may flip slots).
  • The supervisor does not consult the catalogue status. Any shape reachable by phrase (Algorithm 3) is flown if it passes the checks above, whether its catalogue entry is VALIDATED, OFFLINE_CHECKED (never flown), EXPERIMENTAL (flown, criteria failed) or REFUSED (planner declined in the recorded run). Only the mission coordinator (Algorithm 11) restricts itself to VALIDATED shapes. In the snapshot, 1 shape is not VALIDATED: pentomino_w.

9. Comparison with alternatives and related work

Formation reconfiguration combines a goal-assignment problem with multi-robot motion planning. Five established methods are compared.

  • Hungarian method [1]: optimal linear-sum assignment in polynomial time (O(n3) in standard implementations).
  • Auction algorithm [2]: an ε-optimal, parallelisable assignment method in which agents bid for goals; suited to decentralised implementation.
  • CAPT [3]: for interchangeable robots in free space, assigning goals by minimum sum of squared distances and moving all robots on synchronised straight lines yields collision-free trajectories when start and goal positions are sufficiently separated (the paper states the condition in terms of the robot radius R; as we read it, more than 2√2·R).
  • Conflict-Based Search (CBS) [4]: optimal multi-agent path finding on a graph; a high-level search over conflicts adds constraints to single-agent searches, so agents may wait or detour.
  • ORCA [5]: decentralised, reactive collision avoidance; each agent picks a velocity outside the reciprocal velocity obstacles of its neighbours at every control step.

Where this planner is weaker. Its run time is factorial, its conflict test is sampled rather than exact, it assumes a motion model (simultaneous straight lines) that the PD controller does not follow, it never sequences or delays movers, and it treats non-participants as static. [3] gives a guarantee for the same cost function under conditions this catalogue does not meet; [4] would find conflict-free plans in cases this planner refuses. Where it is adequate. For n ≤ 5 the enumeration is exact and fast, the result is deterministic and auditable, and every candidate is checked against the same bounds the supervisor enforces; unsafe cases end in a refusal, never in a squeezed formation.
