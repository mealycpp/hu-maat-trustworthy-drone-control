1. Purpose and context

A formation show chains transitions; some shape pairs force aircraft to cross closely (for example line → diamond plans a 0.956 m pass, close to the 0.82 m watchdog that would freeze an aircraft mid-show). Before the show, an offline analysis computes a clearance figure for each ordered pair of shapes and the fixed show orders are chosen among transitions with large clearance. The per-pair computation is exactly strategist.plan() (Algorithm 14.1) applied with the fleet placed on the slots of the preceding shape. The 104-shape table is stored in acceptance/results/formation_transitions.json ("offline formation_planner.assign from slots(a,5) at ALT to slots(b,5); 61-sample straight-line clearance (same as strategist.plan)"; its metadata field veto_m is 1.0 m, the value in force when the table was generated). The live Safety Officer veto in strategist.py has since been raised to VETO_M = 1.10 m, with the code comment that live flights came up to about 0.15 m closer than planned (line→diamond 0.96 m planned / 0.81 m flown).

2. Inputs, outputs

  • Input: set of shape keys K (23 flown shapes originally; 104 in the current table); planner constants (MIN_SEP 0.88 m, ALT 1.90 m, BOUND 3.0 m).
  • Output: matrix C[a→b] = tightest planned pass in metres, or null if ASSIGN finds no separation-safe assignment; a show order s1..sm with mini C[si→si+1] above the target margin.

3. Algorithm

Algorithm 18.1 Clearance matrix and order check
Source: acceptance/strategist.py: plan; festival/formation_planner.py: slots, assign
1procedure CLEARANCE-MATRIX(K)
2 for a in K do
3 fleet ← { name_i : (SLOTS(a,5)_i , z = 1.90) for i = 1..5 } // fleet order onto a's slot order
4 for b in K, b ≠ a do
5 try p ← PLAN(b, fleet) // Alg. 14.1: ASSIGN + 61-sample min pairwise distance
6 C[a→b] ← p.clear
7 except no-assignment: C[a→b] ← null
8 return C
9function ORDER-MIN(s_1..s_m, C)
10 return min_i C[s_i → s_{i+1}] // null counts as infeasible
11// selection: candidate orders were composed by hand from transitions with high C;
12// the acceptance target written in formation_show.sh is ≥ 1.23 m (default) / ≥ 1.10 m, minimum 1.109 m (SHAPES20)

The analysis is stateless: the matrix is a pure function of the shape set and planner constants, and nothing is carried between pairs. Instead of a state machine, Figure 18.2 shows where the offline figures and the live checks enter the show.

Figure 18.2 Data flow. Solid arrows: data used automatically; dashed: live positions and the manual feedback by which observed shortfalls led to raising VETO_M.

Note on chaining: the matrix starts each transition from the canonical fleet-order placement on shape a. In a flown chain the aircraft occupy shape a in the permutation chosen by the previous ASSIGN. For the two show sequences below, a chained recomputation (start from fleet-order circle, then carry the assigned permutation forward) gives the same values as the matrix, but this equality is not guaranteed in general.

5. Complexity

|K|(|K|−1) calls of PLAN, each O(5!·41·10 + 61·10): about 5·104 distance evaluations per pair; for |K| = 104, 10 712 pairs ≈ 5·108 evaluations (minutes in pure Python, offline).

7. Properties and limitations

  • Guaranteed: the matrix is deterministic and computed with the same planner code as the supervisor; a null entry means the supervisor would refuse that transition from the canonical placement.
  • Not guaranteed: the figure is a planned straight-line clearance, not a flown one (controller saturation, Algorithm 5); it depends on the starting permutation; the supervisor recomputes the assignment from live positions at dispatch, which may differ.
  • Order selection itself is not automated in the repository (no search code); orders were composed by hand and checked with this analysis.
  • The matrix assumes all aircraft start at ALT = 1.90 m. With LEVELS=1 the show moves each aircraft to a random height in 1.1–2.7 m (or a 3-D height profile) after each shape, so the next transition starts from different heights. For the same assignment this can only increase the sampled 3-D distances (horizontal motion is unchanged, a vertical component is added), but ASSIGN may then choose a different permutation, so the matrix value is not a bound in that case either. The live strategist plan() uses the live z and is not affected.
  • Sampling resolution: for straight synchronised legs the relative position of a pair is linear in the path fraction, so the true minimum can lie between two of the 61 samples; the sampled value overestimates it by at most |d|/120, where |d| is the length of the pair's relative displacement (e.g. ≤ 0.05 m for |d| = 6 m).
  • The Lead's evidence record still states the rule as "tightest pass ≥ 1.0 m" while the veto applied is 1.10 m (text only; the decision uses VETO_M).

8. Comparison with alternatives and related work

Choosing which robot goes to which slot and checking that the simultaneous motions stay separated is a studied problem in multi-robot planning. The table places the implemented method (exhaustive assignment over 5! permutations with sampled straight-line checks, plus an offline matrix) among established approaches.

ApproachIdeaGuaranteeRelation to ours
CAPT, Turpin, Michael & Kumar [1]Assign goals by minimising the sum of squared distances, fly synchronised straight linesProven collision-free in obstacle-free space when start and goal positions satisfy a minimum spacing condition (centralised c-CAPT)ASSIGN uses the same cost and the same synchronised straight-line parametrisation, but rejects permutations by sampling instead of relying on the theorem, and adds a separation margin. We have not checked whether our slot spacings satisfy CAPT's condition.
Conflict-Based Search, Sharon et al. [2]Two-level search: high-level conflict tree, low-level single-agent paths; optimal multi-agent path findingOptimal and complete on discrete graphsPlans arbitrary paths around conflicts; ours only accepts or rejects straight lines and has no fallback path (the supervisor refuses instead).
Quadrotor swarm planning, Hönig et al. [3]Roadmap, discrete planning, continuous trajectory refinement; models downwash with ellipsoidal robot shapesCollision-free trajectories in obstacle-rich environments, dense formationsOurs treats aircraft as points with a spherical margin and ignores downwash; adequate only because the simulation is used.
Continuous collision detection, e.g. FCL [4]Exact first time of contact between moving geometric objectsNo missed contacts between samplesOurs samples 61 (planner: 41) instants; the error bound is given in Section 7.

Honest assessment. The method is simple, deterministic and runs the same code as the supervisor, which makes the matrix easy to reproduce and to audit. It is weaker than the alternatives in every guarantee: it has no completeness (a transition the straight-line planner refuses has no alternative path), no proof of separation (sampled, point robots, no downwash or controller dynamics), and the offline matrix assumes a canonical starting permutation and altitude, which tonight's live run showed overstated the dispatch-time plan by 0.37 m and the flown minimum by 0.62 m (pentomino_f→pentomino_w). The protection in flight remains the supervisor's live recomputation and the 0.82 m watchdog, not this analysis.
