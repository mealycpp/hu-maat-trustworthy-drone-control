# RSCL — HU-MA'AT Algorithm Specifications: Index

Reconfigurable Space Computing Lab (RSCL), Cal Poly Pomona. Director: Prof. Mohamed El-Hadedy.

Date: 2026-11-12

| No. | Algorithm | Summary | PDF |
|---|---|---|---|
| 1 | HU Risk-Asymmetric Confidence Gating and Command-Intent Mismatch Checks | Frozen SmolLM2-135M encoder + trained heads produce an action, per-drone targets and a joint confidence; EXECUTE >= 0.85, CONFIRM >= 0.55, else REFUSE, followed by lexical intent, named-address (exclusion lists; an unresolvable address forces REFUSE) and parameter-range guards and a second threshold check at the supervisor. | 01_hu_confidence_gating.pdf |
| 2 | Symbolic Emergency Channel and emergency_key() Normalisation | Model-free fleet-wide HOLD/LAND: a closed phrase set, tolerant of fleet address and politeness, bypasses the neural model and its thresholds; the supervisor applies safe-direction actions to every aircraft with fresh telemetry, and an emergency landing is latched until touchdown (later non-landing commands are ignored). | 02_symbolic_emergency.pdf |
| 3 | Command Routing between HU and the Deterministic Mission Parser | Fail-closed rule cascade in mission_intents.parse: compound-command refusal, formation/turn/altitude/move parsing to operator-confirmed deterministic proposals, plain_primitive hand-off to the trained HU model, and 'unrecognized' sentences shown to HU but never executed. | 03_command_routing.pdf |
| 4 | Target / Address Resolution with Collectives, Exclusions and Ambiguity Refusal | Deterministic resolution of the addressed aircraft set from names, collectives and EXCEPT lists; hedged, mixed or malformed addresses are refused rather than guessed; a companion exact-set guard with the same exclusion-list parsing rejects model target sets that differ from the stated address and refuses any address it cannot resolve exactly. | 04_target_resolution.pdf |
| 5 | Formation Slot Assignment with Sampled Straight-Line Conflict Checking and Translated Placement (assign_shifted) | Exhaustive permutation search for the minimum sum-of-squared-distance slot assignment whose concurrent straight-line paths, sampled at 41 points, keep 0.88 m between movers and from stationary aircraft; if blocked by non-participants, the whole formation is translated over an 81-candidate ring grid. Catalogue: 105 entries VALIDATED (103 distinct geometries) and 1 EXPERIMENTAL; optional 3D height profiles add purely vertical offsets afterwards. | 05_formation_assignment.pdf |
| 6 | Staggered Layered Take-off (2-Colouring of Close Parked Pairs) | Parked aircraft closer than 0.88 m form a conflict graph that is 2-coloured; one colour climbs first to base + 0.90 m, the other waits QUEUED on the ground until its neighbours pass 1.20 m and then climbs to the base altitude; odd cycles and airborne neighbours overhead are refused. | 06_staggered_takeoff.pdf |
| 7 | Proximity Watchdog, Hold Rules and Parked-Aircraft Handling | 10 Hz runtime rule: an aircraft in FORMATION, MOVE or TAKEOFF that comes within 0.82 m (3D) of a fresh peer freezes its setpoint (HOVER, or GROUNDED and disarmed below 0.30 m); landings are exempt; parked aircraft are actively disarmed; single-aircraft moves are admitted only with a 1.0 m sampled path clearance. | 07_proximity_watchdog.pdf |
| 8 | Swarm (Rigid-Group) Travel in the Arena Frame | Several settled aircraft receive the same arena-frame displacement (forward = +x, right = -y), preserving the formation; admitted only if members are settled, spaced >= 0.88 m, goals in bounds, and every member's sampled straight path keeps 1.0 m from every non-moving aircraft. | 08_swarm_group_move.pdf |
| 9 | Setpoint Tracking, Arrival Detection (MOVE/TURN/TAKEOFF to HOVER) and Stale-Telemetry Skipping | 10 Hz saturated PD velocity tracking with yaw compensation; TAKEOFF, MOVE and TURN return to HOVER only when position, speed and yaw errors fall below fixed thresholds; spins are four 90-degree segments; stale aircraft get no motion and are skipped (and logged) for safe-direction commands, refused for risk-increasing ones. | 09_arrival_detection.pdf |
| 10 | MA'AT Plan Dry-Run Check (/api/plan/check, _PlanScratch) | Read-only validation of up to 12 command steps by running the unchanged supervisor command code on a deep copy of the live state with frozen freshness and a publisher that raises; step 0 is exact, later steps run on a predicted settled state; reports goals and two-phase sampled pairwise minimum separations. | 10_plan_dry_run.pdf |
| 11 | Mission Coordinator: Deterministic Agent Bids, Slot Negotiation, MA'AT Check, Operator Approval and Telemetry-Verified Execution | A closed objective grammar is turned into supervisor steps: per-drone rule-based bids select a team, a bounded nearest-slot negotiation runs, the whole plan is dry-run by MA'AT (with bounded alternative search), and only an operator-approved VALIDATED plan is executed step by step with re-check, dispatch and telemetry verification; deviations hold the fleet. | 11_mission_coordinator.pdf |
| 12 | Hybrid SwarmChat: Learned Intent Routing, Dispatch, Follow-ups and Fallback | Operator chat is classified by HU's frozen SmolLM2-135M encoder plus a trained linear head (11 intents, 0.55 confidence floor), then dispatched to deterministic telemetry answers, recorded health history, a read-only command preview, or grounded local-LLM wording; mission objectives get a PLAN-ONLY coordinator transcript; every learned component has a deterministic fallback and nothing can actuate. | 12_hybrid_swarmchat.pdf |
| 13 | Grounding Validator for Generated Chat Text and Generated-Only Repetition Penalty | Deterministic, conservative rule set that accepts a generated persona sentence only if every numeral, aircraft name, shape, event and state assertion is supported by structured evidence, with no action/authority, feelings, identity, prompt-echo or format violations; generation uses a repetition penalty applied to generated tokens only so grounded prompt facts are not penalised. | 13_grounding_validator.pdf |
| 14 | Team Strategy Round: Self-Interested Proposals, Safety Veto and Leader Min-Max Choice | Specification withheld from this public release pending institutional review; it will be published later. | — |
| 15 | Field Callouts and Celebration Triggers from Telemetry | Specification withheld from this public release pending institutional review; it will be published later. | — |
| 16 | Formation Show Control Loop (Settle Detection, Retry on Transient Refusal, Random Multi-Level Heights, Land/Take-off Loop) | Specification withheld from this public release pending institutional review; it will be published later. | — |
| 17 | Per-Aircraft Health Series, Telemetry Recorder and ArduPilot DataFlash Export | A 4 Hz observer samples the supervisor, estimates velocity by finite differences, computes nearest-neighbour and fleet-minimum separation, a safety status and a synthetic battery, records gaps (never last values) for stale telemetry in bounded 2-minute per-aircraft health series and append-only CSV/JSONL logs, and exports per-aircraft ArduPilot DataFlash-format .BIN files marked SIMULATED. | 17_telemetry_recorder.pdf |
| 18 | Offline Transition-Clearance Analysis for Selecting Safe Shape Orders | For every ordered pair of catalogue shapes, the supervisor's assignment is computed from the first shape's slots to the second's and the synchronised straight-line plan is sampled at 61 points to obtain the tightest planned pass; show sequences are chosen so every consecutive transition stays well above the 1.0 m veto. Reproduced: default 11-shape show min 1.231 m; 20-shape show min 1.109 m. | 18_transition_clearance.pdf |
| 19 | Voice Transcript Normalisation and Spoken-Confirmation Protocol for Corrected Transcripts | Context-limited ASR alias repair (names, 'yalla', 'old' -> 'all' only before flight verbs); an uncorrected transcript proceeds to normal gating, a corrected one is held as a single server-side clarification (75 s) that needs a separate spoken 'yes', except emergency phrases, which act immediately. | 19_voice_clarification.pdf |
| 20 | State-Driven LED "Body Language" with Goal Detection and Rate-Budgeted Change-Only Repaint | A read-only observer maps each drone's supervisor state to an LED colour by a pure priority rule (fault > tight < 1.0 m > talking > goal chase > queued > transit > moving/set > parked), detects formation completion once per manoeuvre, and repaints only changed colours under a shared 10 requests/s token bucket so the simulator's odometry stays fresh. | 20_led_body_language.pdf |
| 21 | Drone Voices: Per-Drone Voice Assignment without Reuse, Radio Squelch, Turn-Taking Queue and Urgent Interrupt | Specification withheld from this public release pending institutional review; it will be published later. | — |
